# AML / Amgen project — master analysis inventory

**Location of code:** `projects/amgen/scripts/`
**Compiled:** 2026-07-31
**Purpose:** master index of every analysis performed in this project and the scripts that
implement it, as the entry point for the LabArchives notebook entries.

## How to read this document

- Analyses are grouped into **streams**, following the numeric prefix convention used in
  `scripts/` (`0.` … `28.`). Within a stream, letter suffixes (`a`, `b`, `c`, …) are
  successive revisions or variants, and numeric suffixes (`1c1`, `1c2`) are re-runs.
- **Dates are file modification times**, not execution dates. `scripts/` is not under
  version control, so mtime is the only available timestamp. Treat a date as "last time
  this script was edited" — it is a good proxy for when the analysis was active, but it is
  not a record of when a result was produced. Where a rendered HTML report exists, its
  date is a better record of when the analysis actually ran.
- 106 code files at the top level of `scripts/` are covered here, plus 31 archived files in
  `backup/`, `deprecated/` and `_backup_surfaceome_pipeline_v1/`.

**Companion files in this folder**

| File | Contents |
|---|---|
| `01.script_index.csv` | One row per script: edit date, stream, the output it writes, that output's date range and file count, and flags for stale or missing output. |
| `02.output_directory_map.md` | One row per `results/` directory: date range, file count, and the scripts that write or read it. |

# Notes and caveats

**Dates are edit times, not run times.** No version control on `scripts/`, so mtime is all
there is. Rendered HTML dates are reliable; script dates are not. Anything requiring an
exact experimental date should be checked against the cluster job logs in `scripts/logs/`
(130 files) or the SLURM accounting records.

**Number reuse.** The same prefix means different analyses in several places, which will
confuse anyone reading the notebook later:

| Number | Meanings |
|---|---|
| 11 | `11.integrate.R` vs `11.harmony.R` |
| 12 | `12.identify_cancer_cells.R` (May) vs `12.data_integration.R` (Jun) |
| 13 | `13.CITE_residuals.R` (May) vs `13.numbat_annotation.R` (Jun) |
| 21 | `21.snRNP_expression.R` vs `21.run_qc_report.Rmd` |
| 22 | `22.proteome.R` vs `22.patient_qc_report.Rmd` |
| 23–29 | current top-level scripts vs `_backup_surfaceome_pipeline_v1/` |

`12c` and `12d` each name two different scripts, distinguished only by suffix
(`_501`, `_noDoublets`).

**Superseded run.** Run `260423_VH01624_453_222HWMYNX` was replaced by the re-sequenced
`260522`. Scripts `7c.evaluate_DSB.R`, `9.copykat.R` and `14.surfaceome_trial.R` still
point at it; their results should not be treated as current.

**Scripts vs pipeline.** Much of this work has since been productionised into a Nextflow
pipeline (`amgen/nextflow/`) writing to `results_nf/`. Later scripts here read from
`results_nf/` rather than re-deriving results. `25.trial_test_unhashed_donor_demux.sh`
states the convention explicitly: trial and diagnostic scripts stay in `scripts/`, never in
`nextflow/`. This inventory covers `scripts/` only; the pipeline is not catalogued here.

**Untracked.** `27.removeme_quick_biotin_test.R` and the `remove_me/` project directory are
marked disposable but still present.
